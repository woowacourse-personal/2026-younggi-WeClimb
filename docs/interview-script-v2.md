# 솔루션 검증 인터뷰 스크립트 v2 (10분, 데모 기반)

> v1(문제 검증)과 다른 점: 질문이 아니라 **태스크 중심**. 보여주고 설명하지
> 말고, 폰을 건네고 시키고, 막히는 곳을 관찰한다.
> 데모: https://share.gemini.google/Vb9prWpfzEEP

## 이번에 검증하는 것

| # | 가설 | 판정 재료 |
|---|---|---|
| A | 기록 플로우(세션 시작→칩→한 바퀴 돌아보기)가 **설명 없이** 이해되고 가볍게 느껴진다 | 태스크 1 관찰 |
| B | [내보내기·가설5 잔여] 리캡 카드/오버레이를 실제로 인스타에 올리고 싶어한다 | 태스크 3 + 질문 |
| C | V등급 추정을 신뢰하고, 올리고 싶은 숫자로 느낀다 | 태스크 2 반응 |
| D | 커밋먼트 — 말이 아닌 행동(베타 신청, 지인 공유)이 나온다 | 마무리 |

## 원칙

- **설명하지 않는다.** "기록 앱이에요" 한 마디만 하고 폰을 건넨다. 내가
  설명해버리면 온보딩 없이도 이해되는지 검증이 불가능해진다.
- **think-aloud**: "보이는 대로, 생각나는 대로 소리 내서 말해주세요."
- 막혀도 **돕지 않는다.** 10초 기다렸다가 "지금 뭘 찾고 있어요?"만 묻는다.
- 칭찬("좋네요", "이쁘다")은 기록하지 않는다. **행동과 구체 발언만** 데이터.
- "쓸 거예요?"는 절대 묻지 않는다. 대신 커밋먼트를 요청한다(마무리 참조).

## 스크립트

### 0. 인트로 (30초)

> "지난번에 얘기해주신 걸 바탕으로 데모를 만들어봤어요. 오늘은 제가 설명을
> 안 하고 그냥 드릴 테니까, 쓰면서 보이는 대로·생각나는 대로 소리 내서
> 말해주세요. 잘 안 되면 그건 님 잘못이 아니라 제 설계 잘못이에요."

(신규 인터뷰이라면: 클라이밍 빈도/주 암장/구력만 30초 스크리닝 추가)

### 1. 태스크 1 — 기록 플로우 (4분) ★ 이번 인터뷰의 심장

> "어제 클라이밍 갔다 왔다고 치고, 이 앱으로 그 세션을 기록해보세요."

**관찰 체크리스트 (질문하지 말고 지켜보기)**
- [ ] 암장 검색 → 세션 시작까지 막힘 없이 가는가
- [ ] 세션 중 화면에서 색깔 칩의 의미를 바로 이해하는가
- [ ] "세션 종료 → 한 바퀴 돌아보기"에서 뭘 해야 할지 아는가
- [ ] 하이라이트 추가에서 벽 선택 "모름"을 쓰는가 / 머뭇거리는가
- [ ] 체감 난이도 3버튼을 설명 없이 이해하는가
- [ ] 전체 완료까지 걸린 시간: ___분 ___초

**끝난 뒤 질문**
- "지금 이거, 실제로는 **언제** 할 것 같아요? 암장에서? 집 가는 길에?"
  (세션 후 일괄 입력 가설 — #1 "한 바퀴 회상", #3 "빡빡하고 나감" 재확인)
- "실제 님 세션이었으면 뭐가 달랐을 것 같아요? 입력하기 애매한 게 있었어요?"
- (지난 인터뷰이 #3에게) "지난번에 '어떻게 기록해야 될지 모르겠다'고
  하셨는데, 이 방식이면 그 문제가 풀려요?"

**신호 ✅**: 30초 내 완주, "오 이 정도면 하겠는데", 체감 투표에 즉답
**신호 ❌**: 한 바퀴 돌아보기에서 "이걸 왜 또 해요?", 벽 선택에서 이탈,
"이거 매번 하라고요?"

### 2. 태스크 2 — 성장 탭 (2분)

> "이제 [성장] 탭 눌러보세요." (그리고 침묵 — 첫 반응이 데이터)

- "이 V3라는 숫자, 어떻게 느껴져요? **믿을 만해요?**"
  (계산 근거 설명을 읽는지, "이게 뭔 기준이지?" 하는지)
- "이 숫자가 올라간다면, 다음에 암장 가는 이유가 될 것 같아요?"
- (#1에게) "지난번에 실력을 '동호인 기준'이라고 하셨는데, 앞으로 누가
  물으면 'V3'라고 답할 것 같아요?"

**신호 ✅**: "오 나 V 몇이지?" (자기 걸 궁금해함), 등수/비교 질문이 나옴
**신호 ❌**: "이 숫자 근거가 뭐예요?"에서 설득 안 됨, 무반응

### 3. 태스크 3 — 리캡 카드 + 가설 5 (2분) ★ 3번 놓친 질문, 이번엔 필수

> "성장 탭 아래 '7월 리캡' 카드 보이죠. 그거 눌러보세요."

- **"이거 님 실제 데이터라면, 인스타에 올려요? 본계요 부계요?"**
- "평소에 완등 영상 올릴 때 올리기 전에 뭐 해요? 자르거나, 캡션 쓰거나?"
  (가설 5의 원질문 — 이번엔 반드시)
- "영상에 '닻 클라이밍 · 파랑' 같은 게 자동으로 박혀서 나온다면,
  지금 올리는 방식이랑 뭐가 달라요?"

**신호 ✅**: "이건 올리지" 즉답, 편집 마찰 일화("앞부분 자르는 게 일"),
부계 언급(알아봐줄 사람에게만)
**신호 ❌**: "굳이 이걸 왜 올려요", 편집 안 하고 원본 그대로 잘만 올림

### 4. 부정 질문 (1분) — 예의상 칭찬 걷어내기

- **"이 세 탭 중에 하나 없애야 한다면 뭐 없앨래요? 왜요?"**
- "제일 별로인 거, 안 쓸 것 같은 거 하나만 꼽으면?"

(긍정 질문보다 부정 질문이 정직한 답을 끌어낸다. 여기서 나온 답이
사실상 P0/P1 우선순위 검증)

### 5. 마무리 — 커밋먼트 테스트 (30초) ★ 이번 인터뷰의 결론

말 대신 행동을 요청한다. 수락 여부 자체가 데이터:

1. "베타 나오면 설치 링크 보내드릴게요. **연락처(또는 인스타) 알려주실래요?**"
2. "크루분들 중에 이거 보여줄 만한 분 있으면 **지금 이 데모 링크
   공유해주실래요?**" (누구에게 몇 명에게 보내는지 기록)

**둘 다 수락 = 진짜 신호. 둘 다 회피 = 지금까지의 칭찬 전부 무효.**

## 판정 기준

- **A (기록 UX)**: 설명 없이 완주 + "언제 할지"에 구체적 답 → P0 설계 확정.
  막히면 막힌 지점이 곧 다음 수정 과제.
- **B (내보내기)**: 편집 마찰 일화 + "올린다" → P1 오버레이 확정.
  "원본 그대로 잘 올림" 다수면 오버레이를 P2로 강등.
- **C (V등급)**: 신뢰 안 되면 기능을 빼는 게 아니라 **근거 표시 방식**을
  고친다 (숫자보다 "상위 30%" 같은 상대 표현 검토).
- **D (커밋먼트)**: 3명 중 2명 이상 베타 신청 → 빌드 착수 신호.
  0~1명이면 데모가 아니라 가치 제안 자체를 재점검.
