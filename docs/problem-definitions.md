# 불편 → 문제정의 초안

> 형식: 불편(구체적 장면) → 문제정의(해결책 언급 없이 일반화) → 가설(한 문장) → 프로토타입 URL
> 사용법: 하루에 하나씩 제출. 불편의 디테일(암장 이름, 색깔, 기간)은 실제 경험으로 교체할 것.

---

## 핵심 문제정의 (앱 전체를 꿰는 문장)

**불편**
두 달을 매달린 문제를 드디어 완등했다. 그 순간이 짜릿해서 영상을 찍어 인스타그램에
올렸지만, 클라이밍을 모르는 친구들 피드에 묻혀 "오 운동하네" 한 마디로 끝났다.
몇 주 뒤 세팅이 바뀌자 그 문제는 세상에서 사라졌고, 내가 뭘 해냈는지 증명할 방법도,
알아봐줄 사람도 없었다.

**문제정의**
볼더링의 성취는 세팅 교체와 함께 휘발된다. 완등의 순간을 남길 곳도, 그 가치를
알아보는 사람에게 자랑할 곳도, 실력이 늘고 있음을 확인할 척도도 없어서
"다음 문제에 도전할 동기"가 개인의 의지에만 맡겨져 있다.

**코어 스테이트먼트**
> 완등의 순간을 가장 쉽게 남기고, 알아보는 사람들에게 자랑하고,
> 그 인정을 다음 도전의 동기로 되돌려주는 앱.

**코어 루프**

남긴다 → 자랑한다 → 인정받는다 → 동기를 얻는다 → (다시 도전한다)

코어 루프는 유지하되, "자랑한다"의 **장소**가 단계별로 이동한다:
초기에는 인스타그램(이미 있는 남의 네트워크), 밀도가 생기면 앱 내부로.

## 콜드스타트 전략 (도구로 모으고, 네트워크로 잠근다)

릴스식 피드는 네트워크 밀도가 있어야 가치가 생기므로 **가장 마지막에 켠다.**
대신 N=1에서 가치 있는 기록 도구로 시작하고, 도구 사용이 곧 소셜 콘텐츠
생산이 되도록 설계한다 (Instagram이 필터 앱에서 시작한 것과 같은 구조).

| 단계 | 정체성 | 내용 | 켜지는 기능 | 필요 유저 |
|---|---|---|---|---|
| 1단 | 클라이밍 전용 카메라 (MVP) | 앱 내 촬영 → 성공/실패 분류 → 실패 일괄 삭제 → 앞뒤 트리밍 → 갤러리 저장 + 자동 카운트/아카이브. 검증 질문: "등반 내내 이 앱으로만 찍는가" | 촬영 파이프라인, 카운트·태깅·아카이브 | 1명 |
| 2단 | 자랑은 인스타에서 | 인스타 업로드 원플로우 + 오버레이 + 세션 요약 카드 → 유입 채널. 이후 V등급·리캡·체감투표(옵셔널) | 인스타 원플로우, 리캡(⑬), V등급(②) | 1명 (팔로워는 인스타 것) |
| 3단 | 암장 단위 소셜 | 한 지점 활성 유저 20~30명 넘으면 **그 암장에 한해** "다른 사람 영상 보기" 오픈. 내 기록이 남의 베타가 되는 순간. 되면 옆 지점으로 복제. **오픈할 암장은 우리가 고르지 않고 기록 밀도 데이터가 고른다** | 루트 페이지(④), 베타 요청(⑭), 댓글(⑩) | 암장당 20~30명 |
| 4단 | 피드 | 지점 복제로 밀도가 충분해지면 릴스식 피드. B2B는 쌓인 데이터의 수익화 | 피드(①), 세터 대시보드(⑫), 약점 분석 | 수천 명+ |

**원칙**

- **도구 사용 = 콘텐츠 생산.** 기록에 붙인 영상+루트 태그가 3단에서 그대로
  베타 콘텐츠가 된다. 소셜 오픈은 "기능 출시"가 아니라 이미 쌓인 창고의 문을
  여는 것이어야 한다.
- **데이터 모델은 1일차부터 소셜용.** 기록을 "파랑 3개" 같은 숫자로 저장하면
  나중에 못 연다. 반드시 루트 엔티티(지점 × 벽 × 세팅 회차 × 색깔)에 연결한다.
  ※ 인터뷰 #1 교정: 세팅은 월 1회 일괄이 아니라 **벽 단위 주간 순환** —
  "세팅 월"이 아니라 벽별 세팅 회차로 모델링할 것.
- **성패의 관건은 태깅 UX.** 루트 태깅이 10초 안에 끝나야 도구 단계가 성립한다
  (Day 2 가설). 이 가설이 콜드스타트 전략 전체를 쥐고 있다.
- **함정 회피.** 암장 정보(⑧)·대회 정보(⑨)로 유저를 모으지 않는다 — 정보만
  얻고 떠나는 유저는 콘텐츠를 남기지 않아 소셜 전환이 안 된다.

**검증 우선순위**: 쐐기가 기록 도구이므로 Day 2(기록·태깅)가 최우선,
그다음 Day 3(실력 척도, 2단의 동기 장치), Day 1(베타 영상)은 3단의 예비 검증.

## MVP 문제정의 (2차 인터뷰 반영 확정본 — 2026.07.14)

> 클라이머는 완등의 순간을 아카이빙하고 싶어하고, 아카이빙할 **곳**은 이미
> 있다(인스타 부계면 충분하다). 문제는 거기까지 가는 **과정**이다: 한 세션에
> 50~100개씩 쌓이는 시도 영상 속에서 성공 컷을 골라내고(멀리서 찍어 구분도
> 안 된다), 앞뒤의 죽은 시간을 잘라내고, 무슨 문제였는지 표기하는 정리
> 노동이 등반 시간보다 길다. 그래서 성취의 영상은 정리되지 못한 채 앨범에서
> 죽거나, 고깃집에서 말없이 영상만 자르는 밈이 된다.

**가설**: 촬영 → 성공/실패 분류 → 트리밍 → 기록 → 인스타 업로드를
한 플로우로 묶어 정리 노동을 없애면, 클라이머는 등반 내내 이 앱으로만
찍을 것이다.

※ 확정 근거: #6 티온 본인의 교정 "아카이빙 할 곳이 없는 게 아니네. 과정과
분류 작업이 너무 오래 걸리는 거야"(본인 확인: "정확히, 아주 정확히"),
#4 티뉴 "영상 50~100개, 구분도 안 가, 정리 진짜 귀찮다", #6 "편집에 한두
시간, 등반 시간보다 편집 시간이 길다". 장벽①(분류 체계 부재)은 보조 문제로
강등 — 체계는 촬영 플로우 안에서 자연스럽게 부여한다.

## 솔루션 정의

> **"클라이밍 전용 카메라" — 등반 내내 이 앱으로만 찍으면, 분류·트리밍·
> 기록·인스타 업로드가 저절로 끝난다.**
>
> 앱 안에서 촬영하고, 시도가 끝날 때마다 성공/실패 버튼 하나로 분류한다.
> 실패 컷은 일괄 삭제(선택), 성공 컷은 앞뒤가 잘려 갤러리에 저장되고,
> 그 순간 카운트·색깔 태깅·통계가 부산물로 쌓인다. 세션이 끝나면 성공
> 영상들을 바로 인스타에 올리는 데까지가 한 플로우. 영상은 로컬+인스타에,
> 서버에는 기록(메타데이터)만 — 비용 구조도 이 설계가 해결한다.

**문제 → 솔루션 대응 (2차 인터뷰 반영)**

| 문제 | 솔루션 메커니즘 | 근거 |
|---|---|---|
| 성공 컷 추리기 (50~100개 속에서) | 촬영 직후 성공/실패 버튼 → 실패 일괄 삭제 추천 | #4 #6 |
| 앞뒤 죽은 시간 자르기 | 저장 시 구간 자르기 (수동 → 자동 트리밍 진화) | #6 "①+②만 해줘도 쓴다" |
| 무슨 문제였는지 표기 | 촬영 시작할 때 색깔 선택(카운터형) 또는 업로드 시점 선택(하이라이트형) — 문제 단위 인덱스로 시도 영상 묶음 | #4 #5 |
| 앱↔카메라 왔다갔다 | 앱 내 촬영 | #4 본인 제안, #6 "등반 내내 이 앱으로만" |
| 척도 부재 (상위) | V등급 추정 + 체감 난이도 투표(**옵셔널** — 강제 노출 금지) | #5 반감 반영 |
| 자랑 (상위) | 세션 종료 → 인스타 업로드 원플로우, 월간 리캡 | #4 "집 가는 길에 인스타용 정리" |

**아닌 것**: 범용 편집 앱(CapCut과 안 싸움 — 클라이밍 영상에 특화된
선별·트리밍만), 소셜 앱(3~4단 전까지), 암장 정보 앱(올라가 이미 잘함 —
혼잡도·암장 정보로 경쟁하지 않는다. 올라에 없는 영상 파이프라인이 우리 것).

**숨은 설계 의도**: 유저는 "클라이밍 전용 카메라"를 쓰지만, 촬영 플로우가
남기는 태깅 데이터(지점×색깔×성공여부)가 미래의 루트별 베타 DB와 V등급
통계를 짓고 있다 — 도구 사용 = 소셜 자산 생산. 콜드스타트 전략은 그대로
유효하다.

## MVP 정의 (1~2단)

> **"이 앱으로 찍으면, 고르고·자르고·기록하고·올리는 게 저절로 끝난다"
> — 클라이밍 전용 카메라.** (2차 인터뷰 피벗 반영, 2026.07.14)

유저에게는 "클라이밍 카메라 + 기록"으로 보이는 앱. 3단에서 "어느 날 내
암장 다른 사람들의 베타가 보이는" 전환을 위해, 촬영 플로우가 남기는 태깅
데이터를 처음부터 쌓는다.
※ 아래 "포함 기능" 표는 1차 기준 — 최신 우선순위는 "MVP 내부 우선순위"
절이 정본.

**포함 기능**

| 기능 | 역할 |
|---|---|
| 세션 기록 (지점·시간·푼 문제) | 쐐기의 뼈대. N=1 가치 |
| 루트 태깅 (지점×벽×색깔×월, 10초 UX) | 카메라 앨범과의 차별점이자 미래 소셜 자산 |
| 영상 첨부 + 자동 트리밍(⑮) | 영상은 기록의 첨부파일 |
| 체감 난이도 투표 ("이거 핑크 맞아? 빨강 수준인데") | 인터뷰 #1에서 유일하게 유저가 먼저 꺼낸 니즈. 완등 기록 시 원탭 투표 — V등급 추정(②)의 원료이자 참여 장벽 낮은 첫 소셜 데이터 |
| 인스타 내보내기 — 루트 정보 오버레이, 월간 리캡 카드(⑬) | **성장 채널. MVP에서 빼면 유입이 없다** |
| V등급 추정(②), 탈거 D-day(⑪) | 리텐션·동기 장치 (데이터 쌓이는 대로) |

**MVP 내부 우선순위** (2차 인터뷰 피벗 반영 — 촬영 파이프라인이 심장)

- **P0 (첫 배포 — "클라이밍 전용 카메라" 성립)**
  1. 루트/세션 데이터 구조 — 지점 마스터(공개 지도 데이터) + 색깔/벽은
     lazy creation. 필수 입력은 지점+색깔뿐. 영상은 서버에 안 올림
     (로컬 갤러리 저장 + 서버엔 메타데이터만)
  2. 앱 내 촬영 + 성공/실패 버튼 — 촬영 종료마다 원탭 분류, 문제 단위
     인덱스로 시도 영상 묶기 (#4 제안 구조)
  3. 실패 영상 일괄 삭제 추천 ("이거 빼고 다 지우기" — 강제 아닌 선택)
  4. 성공 영상 앞뒤 수동 자르기 — 저장 직전 간단 트리밍 UI
     (#6 "앞뒤 자르기+실패 분류만 해줘도 쓴다")
  5. 카운트/아카이브 — 촬영 플로우의 부산물로 자동 축적, 날짜별 하이라이트
     뷰. 영상 안 찍는 문제는 색깔 칩 탭으로도 카운트 가능 (카운터형 지원)
- **P1 (첫 달 내 — 원플로우 완성과 유입)**
  6. 인스타 업로드 원플로우 — 세션 종료 → 성공 영상 골라 스토리/릴스로.
     루트 정보 오버레이 포함 (성장 채널)
  7. 체감 난이도 투표 — **옵셔널 노출** (#5 반감 반영), V등급 원료
  8. 세션 요약 카드 — 당일부터 자랑거리
- **P2 (데이터·기술 쌓인 뒤)**
  9. 자동 트리밍 (시작/종료 자동 감지) — 수동 자르기의 진화형
  10. 들찍 모드 (사람 따라가는 자동 프레이밍) — #6 "그것만 해도 원탑".
      차별화 킬러 후보, 미디어파이프 계열로 기술 검증 선행
  11. 월간 리캡 카드, V등급 추정 (단순 규칙부터)
  12. 색깔 자동 인식, 성공 자동 판정 — "더할 나위 없다" 급, 최후순위
  13. 탈거 D-day — 유저 신고 기반, B2B 시점에 정식화

**제외 (나중에)**

- 앱 내에서 남의 영상 보기 — 루트 페이지(④), 베타 요청(⑭), 댓글(⑩): 3단 (암장당 20~30명 후)
- 릴스식 피드(①), 세터 대시보드(⑫): 4단
- 암장 정보(⑧)·대회 정보(⑨): 함정 회피

**주의: "공유"는 두 가지**

- 밖으로 공유(인스타 내보내기) = MVP부터. 유저는 어차피 인스타에 올린다 —
  우리를 거치면 예쁘고, 결과물이 앱 홍보가 된다.
- 안에서 공유(남의 영상 보기) = 밀도가 생긴 뒤. "나중에 넣는 공유"는 이것만이다.

**아닌 것**: 영상 보관·편집만 제공하는 앱 — 그건 카메라 앨범+CapCut과 싸우는
것이고, 루트에 안 묶인 영상 더미는 3단에서 열 창고가 되지 못한다.

## Day 1 — 베타 영상

**불편**
암장에서 2주째 같은 파랑 문제에 막혀 있었다. 다른 사람은 어떻게 푸는지 보고 싶어서
인스타그램에 암장 해시태그를 검색했지만, 수백 개 영상 중에 '그 벽, 그 문제' 영상을
찾는 건 운에 가까웠고, 결국 못 찾은 채 세팅이 교체됐다.

**문제정의**
볼더링에서 막힌 문제를 푸는 가장 효과적인 방법은 다른 사람의 시도(베타)를 보는 것인데,
특정 암장의 특정 문제에 대한 영상을 찾을 수 있는 방법이 없다.

**가설**
"지점 > 벽 > 색깔"로 루트를 특정해 그 문제의 영상만 모아 보여주면,
클라이머는 인스타그램 해시태그 검색 대신 이것을 쓸 것이다.

**프로토타입**
- 화면: 루트 상세 — 문제 정보(지점·벽·색깔·세팅 월) + 영상 그리드 + 완등률 뱃지
- URL: (Gemini Canvas 링크)

## Day 2 — 기록

**불편**
클라이밍을 1년 넘게 다녔는데, 지난달에 뭘 풀었는지 기억이 나지 않는다.
메모장에 "파랑 3개, 남색 1개"라고 적어봤지만, 세팅이 바뀌고 나니
어느 문제였는지도 알 수 없는 의미 없는 기록이 됐다.

**문제정의**
볼더링은 매달 문제가 통째로 교체되기 때문에, 내가 무엇을 얼마나 풀었고
실력이 늘고 있는지를 누적해서 확인할 방법이 없다.

**가설**
색깔 버튼을 탭하는 것만으로 문제가 기록될 만큼 입력이 가볍다면(10초 이내),
클라이머는 매 세션 기록을 남길 것이다.

**프로토타입**
- 화면: 세션 기록 — 색깔 칩 탭 → 카운트, 세션 타이머, 종료 시 요약 카드
- URL: (Gemini Canvas 링크)

## Day 3 — 실력 척도

**불편**
"너 V 몇 해?"라는 질문에 답을 못 했다. 다니는 암장에서는 남색을 푸는데,
다른 암장에 가면 같은 색도 전혀 못 풀었다. 내 실력이 어느 정도인지 나도 모른다.

**문제정의**
암장마다 난이도 기준(색깔 테이프)이 제각각이라, 클라이머가 자신의 실력을
객관적인 척도로 파악하거나 다른 사람과 비교할 방법이 없다.

**가설**
완등 기록으로부터 V등급 추정치를 계산해 보여주면,
클라이머는 이 숫자를 올리기 위해 기록을 계속 남길 것이다.

**프로토타입**
- 화면: 프로필 — V등급 게이지 + 월별 성장 그래프 + "다음 등급까지 남은 것"
- URL: (Gemini Canvas 링크)
