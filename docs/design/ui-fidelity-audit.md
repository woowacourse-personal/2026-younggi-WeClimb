# UI 시안 충실도 감사

갱신일: 2026-07-29

## 기준

- 시각 정본: `design-bundle/00-common.html`부터 `design-bundle/11-records.html`
- 토큰 정본: `design-system/we-climb/MASTER.md`의 Stack Adaptation과 UI 폴리시
- 기준 폭: 앱 내부 콘텐츠 390dp
- 제외: HTML의 기기 프레임과 가짜 상태바
- 실제 연결 영역: 촬영은 CameraX `PreviewView`, 트리밍과 재생은 Media3 플레이어

빌드 성공 여부나 기존 Compose 코드를 시각 충실도의 증거로 사용하지 않는다. 화면별
텍스트, 섹션 순서, 고정 영역, 상태 변형을 먼저 맞추고 390dp 캡처로 다시 판정한다.

## 공통 결함

- `WeClimbTheme`이 Barlow와 Barlow Condensed를 등록하지 않아 기본 Android 서체로
  표시됐다.
- 제품 화면에 테스트용 미리보기 이동 행동이 섞였다.
- 일부 화면은 시안의 고정 하단 영역을 스크롤 본문 안에 배치했다.
- 텍스트 기호를 임시 아이콘으로 사용한 곳이 있다. 구조 안정화 뒤 벡터 자산으로
  교체한다는 Master 정책에 따라 이번 패스에서는 위치와 크기부터 고정한다.

## 검증 환경 기록

- Galaxy S23 `SM-S911N`의 현재 물리 해상도는 1080x2340, Android 논리 밀도는
  480dpi, 글자 배율은 1.0이다.
- 이 설정의 앱 폭은 360dp라서 390dp 정본보다 좁다. 기기 전역 밀도는 변경하지
  않는다.
- 실제 기기에서는 360dp 축소 대응과 CameraX, Media3 배치를 확인한다.
- 계약의 390dp 시각 판정은 별도 재현 가능한 캡처 표면에서 수행한다.

## 390dp 재검증 결과

디버그 빌드의 `UiCatalogActivity`는 실제 기기 폭을 앱 내부 390dp로 고정하고
정상, 오류, 완료, 시트, 다이얼로그 상태를 intent extra로 재현한다. 이 액티비티는
debug source set에만 있으며 제품 탐색에는 노출되지 않는다.

기존 구현을 기준으로 삼지 않고 캡처를 다시 대조하면서 아래 결함을 추가로 발견해
수정했다.

- 온보딩의 가운데점, 성공/실패 표기, 허용 상태의 보조 문구가 HTML과 달랐다.
- 검색 결과의 일치 문자열이 주황색으로 강조되지 않았다.
- 보드의 색 막대가 `Surface` 최소 제약 때문에 모든 색에서 전체 폭으로 보였다.
- 트리밍과 재생에서 Media3 기본 컨트롤이 시안의 커스텀 컨트롤 위에 겹쳤다.
- 재생 오버레이를 열어도 아카이브 하단 탭이 남았다.
- 아카이브 날짜에 시안에 없는 연도와 다른 날짜 형식이 표시됐다.
- 기록 탭의 6개월 차트가 누적 막대가 아니라 색상별 단일 막대로 축약됐다.
- 공통 권한 설정 카드가 독립적으로 재현되지 않았다.

수정 뒤에는 로딩, 성공과 오류 배너, 권한 카드, 온보딩 3상태, 홈, 암장 목록,
보드와 종료 다이얼로그, 촬영 상태, 미디어 처리 시트, 트리밍 4상태, 아카이브
4상태, 전체 화면 재생, 세션 종료, 리포트, 기록 탭을 각각 390dp에서 캡처할 수
있다. Galaxy S23에서는 CameraX 준비, 녹화, 분류 상태에 인라인 배너가 겹치지
않는 것도 별도로 확인했다.

2026-07-29 최종 자동 검증에서는 모든 승인 상태를 `UiCatalogActivity`로 열고
각 상태의 핵심 접근성 표면을 확인한 뒤 스크린샷 파일이 실제 생성되는지 검사했다.
보드의 흰색 40% 진행량과 파랑·초록 이중 톤은 최신 APK를 Galaxy S23에 설치해
다시 캡처했다. 제품 UI는 화면별 파일로 분리했고 호출되지 않던 구형 Compose
화면은 제거했다.

이 결과는 S13의 최종 수동 승인 대신 사용할 수 없다. S13은 frozen 계약대로 별도
후속 목표에 남기고, 현재 목표에서는 재현 가능한 캡처 표면과 자동 검증까지만
완료 증거로 사용한다.
