# 외부 데이터 획득 및 크롤링 정책

> 상태: Phase 1 범위 확정
> 대상: Phase 1 암장 지점 선택과 초기 시드 데이터
> 결정일: 2026-07-21

## 목적과 범위

Phase 1에는 암장 **지점명, 주소**만 필요하다. 좌표는 지도 기능을 추가할 때
승인된 제공사에서 보강한다. 벽, 문제, 등급, 사진, 리뷰, 운영자나 이용자
정보는 범위 밖이다. 이 문서는 "공개로 보인다"는
사실을 수집 허가로 해석하지 않도록 출처, 보관, 표시, 갱신의 기준을 고정한다.

영상은 기기에만 저장하고 서버에는 세션 메타데이터만 둔다는 기존 결정은
유지한다. 이 문서는 법률 자문이 아니라, 구현 전에 통과해야 하는 운영
통제 기준이다.

## Phase 1 결정

초기 출시에는 **서울의 수동 검증 지점 목록**만 넣고, 장소 검색 API는
연결하지 않는다. 각 항목은 암장 공식 웹사이트나 운영자에게 직접 확인하고,
`sourceUrl`, 확인일, 확인자를 남긴다. 현재 7개 시드는 개발과 첫 서울 필드
테스트에 유지한다. 원본은 `docs/data/seoul-gym-seed.csv`로 관리한다. 추가
시드는 크루의 실제 방문권이 넓어질 때 보강한다.

이후 검색을 붙일 때는 HTML 크롤링 대신 하나의 공식 장소 검색 API만 사용한다.
공급자의 약관, 재사용 범위, 캐시 기간, 필수 출처 표기를 검토하고 승인한
뒤에만 연결한다. 예를 들어 Kakao Local은 문서화된 장소 검색 API를 제공하며
장소 ID, 이름, 주소, 좌표를 반환한다. [Kakao Local 개발자 문서](https://developers.kakao.com/docs/en/local/dev-guide)

직접 추가는 사용자가 이름과 대략적 위치를 입력하는 후보 생성이다. 외부
사이트를 자동 조회하거나 보강하지 않으며, 검토 전에는 개인 목록에서만
보인다.

## 명시적으로 금지하는 수집

- 웹페이지, 지도 화면, 인스타그램 등에서 HTML을 자동 수집하거나 파싱하지 않는다.
- 비공개 또는 문서화되지 않은 API, 로그인 세션, 쿠키, 우회 URL을 사용하지 않는다.
- CAPTCHA, 로그인, 유료벽, 접근 제한, 요청 한도를 우회하지 않는다.
- 장소 사진, 리뷰, 이용자나 운영자 개인정보, 지도 타일과 대량 장소 목록을 수집하지 않는다.
- 공개 페이지라 해도 대량 또는 반복 추출로 별도 데이터베이스를 만들지 않는다.

데이터베이스 제작자는 상당 부분의 데이터 또는 정상 이용을 해치는 반복적
추출에 대해 권리를 가진다. [저작권법 제93조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029423451)
접근 권한을 넘는 시스템 이용도 금지된다. [정보통신망법 제48조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028660557)

## 데이터 모델과 보관 기준

지점 레코드는 아래 최소 필드만 가진다.

| 필드 | 용도 |
| --- | --- |
| `gymId` | 내부 식별자 |
| `name`, `address` | 선택과 세션 기록 |
| `latitude`, `longitude` | 지도 기능 도입 뒤에만 사용하는 선택 필드 |
| `sourceType`, `sourceUrl`, `providerPlaceId` | 출처와 재검증 |
| `verifiedAt`, `verificationStatus` | 갱신과 공개 제어 |
| `attributionText` | 공급자 표시 요구 사항 |

`providerPlaceId`는 공급자가 명시적으로 허용한 경우에만 장기 보관한다. 예를
들어 Google Places 콘텐츠는 원칙적으로 사전 수집, 캐시, 저장이 제한되고
`place_id`만 예외적으로 보관할 수 있다. [Google Places 정책](https://developers.google.com/maps/documentation/places/web-service/policies?authuser=31&hl=en)
공급자별 계약이 다르면 더 엄격한 기간을 적용한다. API 결과와 키는 로그에
남기지 않고, 키는 서버 또는 플랫폼 제한된 비밀 저장소에서 관리한다.

## 사용자 보호와 운영

개인정보를 추가로 수집하지 않는다. 이후 사용자 제출이나 신고에 연락처,
이미지, 운영자 정보가 필요해지면 목적, 보관 기간, 처리 근거를 별도로
정의한다. 개인정보 처리는 법정 근거가 필요하다. [개인정보 보호법 제15조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398929)

잘못된 지점은 앱 내 정정 요청 또는 운영 채널로 접수하고, 확인 즉시 수정,
비공개 또는 삭제한다. 출처, 검토 결과, 변경 시각을 import 감사 로그에
남긴다. 제공사 표시가 필요하면 검색 결과와 상세 화면에 그대로 표시한다.

## Phase 1 착수 게이트

다음의 수동 시드 조건이 모두 충족될 때에만 지점 선택 기능을 구현한다.

1. 수동 시드의 출처와 확인일을 가진 5개 이상 목록을 준비한다.
2. 위 최소 필드, 비공개 후보 상태, 정정 처리와 감사 로그를 데이터 설계에 반영한다.

크루 배포 전에는 실제 방문권을 기준으로 시드를 보강한다. 필요한 수량은
크루의 활동 지역을 정한 뒤 결정한다.

장소 검색 API를 추가할 때는 별도로 최신 약관, 가격, 한도, 캐시, 출처 표시,
API 키 제한과 실패 시 빈 검색 상태를 승인하고 구현 계획에 포함한다.

공개 디렉터리를 대규모로 만들거나 상업적으로 확장하기 전, 제공사의 서면
허가 또는 전문 법률 검토를 받는다. Phase 3의 소셜 기능에도 제3자 콘텐츠
크롤링은 추가하지 않으며, 사용자 업로드 권리와 신고, 삭제 정책을 별도
설계한다.

## 후속 작업

- Phase 1 설계에서 지점 repository, 시드 import 형식, 후보 검토 상태를 정의한다.
- 실제 제공사를 선택하면 약관 검토 결과와 UI 출처 표기를 이 문서에 기록한다.
- 로드맵의 "공개 지도 시딩" 표현은 이 문서의 게이트 통과 뒤에만 가능하도록 해석한다.
