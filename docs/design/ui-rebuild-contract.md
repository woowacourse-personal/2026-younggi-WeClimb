# We-Climb 구현 기능 기반 UI 계약과 재구현 계획

## 개요

현재 Android 앱에는 성공 영상의 트리밍, 보관, 재생, 공유와 실패 복구까지의 기능이
구현돼 있다. 그러나 기존 `design-bundle/01`부터 `06`은 기본 사용자 여정의 정적
시안이며, 구현 과정에서 필요한 상태와 행동을 모두 담지 않는다.

이 문서는 기존 bundle과 구현을 비교해 새 design-bundle에 추가해야 할 화면과 상태를
고정한다. 새 bundle을 받은 뒤, 앱 내부 콘텐츠를 Galaxy S23의 390dp 폭 기준으로
시안에 충실하게 Compose로 재구현한다.

## 배경 및 목표

이전 작업은 design-bundle의 색상과 카드 방향을 Compose에 적용하는 수준으로 진행됐다.
따라서 실제 앱은 동작하지만, 기본 Material 컴포넌트와 입력 필드 중심이라 시안의
구조와 다르다.

목표는 기능을 새로 늘리는 것이 아니다. 현재 구현된 기능이 빠지지 않게 새 시안의
입력을 만들고, 이후 새 시안을 기준으로 화면 구조와 상태를 동일하게 구현하는 것이다.

## 범위

### 포함

- 기존 `design-bundle/01`부터 `06`과 현재 Android 구현의 기능 UI 대조
- 새 design-bundle에 필요한 독립 페이지, 페이지 내 컴포넌트 상태, 행동 배치 추천
- 현재 구현된 CameraX, Media3, Room, MediaStore, 재생, Android 공유 흐름 유지
- 아카이브, 앱 내 재생, 권한 거부와 설정 이동, 오류, 세션 종료 확인 상태 포함
- 새 bundle 수령 후 화면별 시안 충실도 Compose 재구현 계획 수립
- 앱 내부 콘텐츠의 390dp 폭 기준 시안 대조

### 제외

- 세션 종료 사진, 리포트 카드, 기록 통계, 리포트 기반 공유의 새 기능 구현
- `07-session-end`, `08-report`, `09-records`의 제품 범위 결정
- 기존 Phase 1 설치본 Room v1 성공 Attempt의 영상 상태 마이그레이션
- HTML의 가짜 기기 프레임, 가짜 상태바를 Android 앱에 재현
- 새 design-bundle을 받기 전의 시각 재구현 시작

## 요구사항

### 기능 요구사항

- 새 시안은 현재 구현된 모든 사용자 행동의 진입점과 결과 상태를 제공해야 한다.
- 카메라, 플레이어, 트리머처럼 실제 Android 뷰가 필요한 기능은 시안의 해당 영역 안에
  연결한다.
- Android 시스템 권한 창과 Android 공유 chooser 자체는 앱 시안으로 만들지 않는다.
  이를 열기 전과 돌아온 뒤의 앱 상태는 시안에 포함한다.
- 기존 bundle에 없는 화면은 새 페이지가 필요한지, 기존 페이지의 상태 컴포넌트로
  충분한지 추천한다.
- 새 시안을 받은 뒤에는 화면별 기준 스크린샷으로 앱 내부 콘텐츠를 대조한다.

### 비기능 요구사항

- 기준 뷰포트는 Galaxy S23의 390dp 폭이다.
- 각 상태의 핵심 행동은 최소 터치 영역과 읽을 수 있는 접근성 라벨을 유지한다.
- 처리 중에는 중복 실행을 막고 진행 상태를 보여 준다.
- 실패와 읽기 불가 상태는 Attempt와 원본 URI를 삭제하지 않는다.
- 시안 충실도의 허용 오차와 스크린샷 비교 방식은 새 bundle 수령 뒤 추가 논의가
  필요하다.

## 설계 개요

### 새 bundle에 필요한 페이지와 상태

| 구분 | 현재 기능 | 기존 bundle 상태 | 새 시안 권장 |
|---|---|---|---|
| `00` 앱 공통 | 초기 로딩, 작업 성공,오류 메시지 | 없음 | 별도 페이지 대신 공통 로딩과 인라인 배너, 오류 컴포넌트 |
| `01` 온보딩 | 권한 요청, 거부 후 설정 이동, 허용 후 다음 단계 | 기본 온보딩만 있음 | 같은 페이지의 `권한 요청 전`, `권한 거부`, `설정에서 허용 후` 변형 |
| `02` 홈 | 암장 선택 시작, 영상 아카이브 진입, 첫 기록 빈 상태 | 기본 홈만 있음 | 홈 안에 아카이브 진입과 첫 기록 빈 상태를 포함 |
| `03` 암장 선택 | 검색어 입력, 개인 암장 추가, 선택, 이름 수정, 숨기기 | 검색과 선택 예시만 있음 | 검색 결과, 개인 암장 추가, 선택됨, 관리 메뉴를 한 페이지 상태로 설계 |
| `04` 세션 보드 | 녹화 시작,중지, 색상별 성공 수, 성공,실패 분류, 영상 처리 선택, 보류 영상 재진입, 아카이브 진입, 세션 종료 확인 | 기본 보드와 촬영 CTA만 있음 | 보드 유지. 성공,실패 분류와 `자르기`, `나중에`, `원본 유지`는 촬영 결과 바텀시트 또는 보드 하단 패널로 배치. 세션 종료 확인은 별도 확인 다이얼로그 |
| `05` 촬영 | 실제 CameraX 프리뷰, 녹화 중, 중지 뒤 성공,실패 선택, 카메라 오류 | 정적 촬영 예시만 있음 | 독립 페이지 유지. 실제 카메라 프리뷰 위에 선택 색상, 녹화 상태, 중지, 성공,실패 제어를 오버레이. 카메라 준비 중과 오류 변형 포함 |
| `06` 트리밍 | 원본 재생, 시작,종료 범위, 완료, 처리 중, 범위 오류, 실패 뒤 재시도, 원본 유지, 나중에, 공유 | 정적 미리보기와 타임라인, 저장, 나중에만 있음 | 독립 페이지 유지. 실제 영상 프리뷰와 타임라인을 기본으로 하고 `대기`, `처리 중`, `오류`, `완료` 변형을 제공. 원본 유지, 나중에, 공유는 하단 행동 영역에 배치 |
| `07` 영상 아카이브 | 성공 영상 최신순 목록, 상태, 날짜,암장,색상, 재생, 공유, 트리밍 재진입, 빈 목록, 읽기 불가 영상 | 없음 | 새 독립 페이지 필요. `빈 목록`, `정상 영상 목록`, `트리밍 대기`, `읽기 불가` 카드 상태 포함 |
| `08` 앱 내 재생 | 선택 영상을 앱에서 재생하고 닫기 | 없음 | 독립 route보다 아카이브 또는 트리밍 위의 전체 화면 재생 오버레이 권장. 닫기와 영상 정보, 공유 진입점 포함 |

### 권장 사용자 흐름

```text
홈
  -> 암장 선택
  -> 세션 보드
  -> 촬영 페이지
  -> 성공 또는 실패 분류
  -> 성공: 자르기 | 나중에 | 원본 유지
       -> 트리밍 페이지
       -> 영상 아카이브
          -> 앱 내 재생 오버레이
          -> Android 공유 chooser
```

### 기존 bundle에 없는 필수 컴포넌트

- 공통 로딩 인디케이터, 성공,오류 배너
- 권한 거부 뒤 설정으로 이동하는 안내 카드
- 촬영 결과의 성공,실패 분류와 영상 처리 선택 바텀시트 또는 패널
- 세션 종료 확인 다이얼로그
- 트리밍 진행 상태, 범위 검증 오류, Transformer 실패 뒤 재시도 상태
- 빈 아카이브, 트리밍 대기 영상, 원본 유지 영상, 트리밍 완료 영상 카드
- 기기에서 삭제돼 읽을 수 없는 영상 플레이스홀더
- 전체 화면 앱 내 재생 오버레이
- 개인 암장 추가와 이름 수정, 숨기기 관리 메뉴

## 영향 범위

- `design-bundle/`: 새 `00` 공통 상태, 갱신된 `01`부터 `06`, 새 `07` 아카이브와
  `08` 재생 시안
- `design-system/we-climb/MASTER.md`: 새 bundle에서 확정되는 토큰, 서체, 아이콘,
  컴포넌트 규칙
- `frontend/androidApp/src/main/kotlin/com/weclimb/android/MainActivity.kt`: 화면 구조와
  navigation, CameraX와 Media3 UI 결합
- `frontend/androidApp/src/main/kotlin/com/weclimb/android/WeClimbTheme.kt`: 서체와 디자인
  토큰
- Android instrumentation 테스트: 화면별 핵심 행동과 상태 전환
- 스크린샷 비교 기준과 실기기 시각 검토 기록

## 리스크 및 미해결 질문

- 새 bundle에서 상태별 변형을 독립 HTML로 둘지, 하나의 HTML 안의 변형으로 둘지는
  디자인 과정에서 결정한다.
- 스크린샷 비교의 허용 오차, 캡처 기기 상태, 비교 도구는 새 bundle 수령 뒤 결정한다.
- 아카이브 썸네일 생성과 대용량 목록 성능 정책은 별도 기능 범위다.
- 새 UI 작업이 끝나기 전에는 Phase 2 후반 기능인 세션 종료 후처리와 리포트 작업을
  시작하지 않는다.
