# We-Climb - 로드맵

> 단계 순서는 도메인 역학(브리프 참조)에서 도출됐다. 각 단계의 task 분해와
> 기술 설계는 design-doc/개발 스킬에서 한다.

## Phase 1 - 세션 루프의 뼈대 (1주차)

- **만들 것, 할 것**: 온보딩(로그인 1개), 홈, 암장 선택(lazy creation), 세션
  보드(칩 카운트), 인앱 촬영+성공/실패, 영상 로컬 저장, 세션 메타 서버 기록 /
  암장 지점 데이터 시딩(출처, 재사용 조건 검증 후), **본인 필드 테스트 1회**
- **왜 이게 먼저인가**: 인앱 카메라가 최대 기술 리스크 - 무너지면 전부
  재설계라 최우선 실기기 검증. 이 시점부터 이미 "쓸 수 있는 앱"(칩 카운트)
- **완료 신호**: 실제 암장에서 한 세션을 앱으로만 찍고 성공/실패가 문제
  단위로 기록됨
- **착수 게이트**: [외부 데이터 획득 및 크롤링 정책](../design/data-acquisition-crawling-policy.md)의
  수동 시드, 제공사 약관, 출처 표시 조건을 충족

## Phase 2 - 원플로우 완성 (2주차)

- **완료된 범위 (2026-07-23)**: 성공 영상의 즉시 트리밍, 나중에 처리, 원본 유지,
  아카이브, 앱 내 재생, `ACTION_SEND` 공유
- **선행 작업**: 현재 구현 기능을 반영한 새 design-bundle을 만든 뒤, 화면별
  시안 충실도 기준으로 Compose UI를 재구현한다. 세부 입력과 순서는
  [UI 재구현 계약](../design/ui-rebuild-contract.md)을 따른다.
- **다음 범위**: 세션 종료 사진과 후처리, 리포트 카드와 기록 통계, 리포트 기반
  공유. 기존 Phase 1 설치본의 성공 영상 상태를 보존하는 Room 마이그레이션 정책도
  이 단계에서 결정한다.
- **완료 신호**: 완료된 미디어 흐름은 실제 기기에서 검증됐다. Phase 2 전체의
  완료 신호인 세션 종료→리포트→공유는 다음 범위가 끝난 뒤 다시 검증한다.

## Phase 3 - 크루 검증 (3주차~)

- **만들 것, 할 것**: 크루 5명 APK 배포, **세션 동행 관찰 1~2회**, 피드백
  루프 / 관찰에서 나온 마찰 제거, 통계 시각화 강화
- **왜 이 순서인가**: 성공 기준이 기능이 아니라 반복 사용 행동 - 만들기를
  멈추고 검증하는 단계가 명시적으로 필요
- **완료 신호**: **크루 5명이 2회 이상 이 앱으로만 찍고 세션 기록을 남김
  (성공 기준)**. 리포트 공유는 다음 Phase 2 범위가 완료된 뒤 함께 관찰한다.

## Phase 4 - 확산 준비 (이후)

- **만들 것, 할 것**: V등급 추정, 월간 리캡, 체감 투표(옵셔널), iOS 빌드(KMP),
  스토어 출시 / 인스타 유입 추적, 암장별 밀도 모니터링(3단 개방 조건:
  암장당 20~30명 ≈ 크루 2~3개)
- **왜 이 순서인가**: 도구 검증 전의 확산은 이탈만 만든다 (콜드스타트 원칙)
- **완료 신호**: 인스타 카드를 보고 온 비지인 유저 첫 가입

## 미룬 것들

- 들찍 모드, 자동 트리밍, 색깔 자동 인식 - 기술 검증 선행 필요

- 계정 동기화 고도화, 랜딩 페이지 - MVP엔 불필요
